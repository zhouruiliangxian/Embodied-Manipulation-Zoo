A3Aspire enables automated discovery of reusable skills that persist across multiple tasks, simulation and real-world settings, and different embodiments. Rather than relying on fixed, human-engineered pipelines, Aspire operates in an open-ended learning loop, consisting of three key components: (1) a closed-loop robot execution engine that exposes fine-grained multimodal traces (e.g., perception overlays, grasp candidates, motion trajectories, and collision feedback), enabling the agent to autonomously diagnose failures, synthesize repairs, and validate outcomes; (2) a continually expanding skill library that distills validated fixes into reusable, transferable robotic knowledge; and (3) an evolutionary search procedure that generates diverse task sequences and control programs, systematically debugging them to explore beyond single-trajectory refinement.

Aspire 能够自动发现可复用技能，并使这些技能跨任务、跨仿真与真实场景、跨不同本体持续留存。它不依赖固定的人工设计流水线，而是在一个开放式学习循环中运行，该循环包含三个关键组件：（1）闭环机器人执行引擎，暴露细粒度的多模态轨迹（如感知叠加图、抓取候选、运动轨迹与碰撞反馈），使智能体能够自主诊断失效、生成修复并验证结果；（2）持续扩张的技能库，把经过验证的修复蒸馏为可复用、可迁移的机器人知识；（3）进化式搜索流程，生成多样的任务序列与控制程序并系统性地调试，从而超越单条轨迹式的精炼。

1. Introduction

引言采用经典"缺口论证"：既有范式可用（P1）→ 缺口一：反馈太粗（P2–P3）→ 缺口二：经验不累积（P4）→ 人类工程师对照（P5）→ 提出方案（P6–P7）→ 结果预览（P8）。

1.1Recent progress in software engineering agents demonstrates that language models can autonomously inspect execution traces, localize failures, revise implementations, and improve through repeated interaction with execution environments. In robotics, this paradigm has inspired code-as-policy systems that compose perception modules, planning APIs, and control primitives into executable robot programs. Because robot behaviors are represented explicitly as programs, they can in principle be inspected, edited, debugged, and refined through interaction feedback.

软件工程智能体的近期进展表明，语言模型已能自主查看执行轨迹、定位故障、修改实现，并在与执行环境的反复交互中不断改进。在机器人领域，这一范式催生了"代码即策略"系统：把感知模块、规划接口与控制原语组合成可执行的机器人程序。由于机器人行为被显式表达为程序，原则上它们就可以被查看、编辑、调试，并借助交互反馈持续精化。

1.2However, existing robotic coding agents remain fundamentally limited by naive execution environments that provide only coarse task-level feedback. Debugging robot programs is intrinsically challenging because failures can arise from many interacting components, including multimodal perception, motion planning, grasp generation, contact dynamics, and long-horizon task coordination. A failed rollout may indicate that the task did not succeed, but not whether the root cause is incorrect perception, an unstable grasp, a planning error, or a downstream recovery failure. Without fine-grained diagnostic traces, agents have limited ability to determine what evidence to inspect, how to localize failures, or what repair strategy to attempt.

然而，现有的机器人编程智能体仍受制于简陋的执行环境——它们只提供粗粒度的任务级反馈。调试机器人程序之所以本质上困难，是因为故障可能源自多个相互耦合的环节，包括多模态感知、运动规划、抓取生成、接触动力学与长时序任务协调。一次失败的 rollout 只能说明任务没有成功，却不能说明根因究竟是感知错误、抓取不稳、规划失败还是下游恢复失效。缺乏细粒度诊断轨迹时，智能体既不知道该查看哪些证据，也不知道如何定位故障、该尝试哪种修复策略。

1.3Moreover, existing systems do not accumulate experience across tasks. Once a task is completed, discovered fixes and recovery strategies are discarded rather than consolidated into reusable skills. As a result, the agent solving its hundredth task is effectively no more experienced than the agent solving its first.

其次，现有系统不会跨任务积累经验。一个任务完成后，所发现的修复手段与恢复策略就被丢弃，而不是沉淀为可复用技能。结果是：解决第一百个任务的智能体，其经验水平实际上与解决第一个任务时毫无差别。

1.4Human robotics engineers take a fundamentally different approach. When a robot program fails, they replay executions, inspect perception outputs and motion trajectories, localize the failing subsystem, revise the implementation, and internalize reusable recovery strategies. Over time, debugging experience compounds into transferable knowledge, including grasp recovery heuristics, navigation strategies, prompting recipes, and procedural fixes that generalize across tasks. This accumulation of reusable knowledge is a key reason why human robot programmers become progressively more effective over time.

人类机器人工程师的做法根本不同。程序失败时，他们会回放执行过程、检查感知输出与运动轨迹、定位出故障的子系统、修改实现，并把可复用的恢复策略内化。久而久之，调试经验沉淀为可迁移的知识，包括抓取恢复启发式、导航策略、提示词配方以及跨任务通用的流程性修复。这种可复用知识的积累，正是人类机器人程序员越做越有效的关键原因。

1.5In this work, we introduce Aspire, a self-improving continual learning robotic system that autonomously writes and refines robot control programs in a code-as-policy paradigm while accumulating experience into a reusable skill library. Rather than operating within a fixed perception-plan-execute pipeline, Aspire runs in an open-ended learning loop, in which the agent self-determines how to inspect execution traces, diagnose failures, synthesize repairs, validate corrected behaviors, and consolidate successful recovery patterns into persistent skills that transfer across tasks.

本文提出 Aspire：一个可自我改进的持续学习机器人系统，它在"代码即策略"范式下自主编写并精化机器人控制程序，同时把经验累积为可复用的技能库。Aspire 不在固定的"感知—规划—执行"流水线中运行，而是运行于开放式学习循环：由智能体自行决定如何查看执行轨迹、诊断故障、生成修复、验证修正后的行为，并把成功的恢复模式固化为可跨任务迁移的持久技能。

1.6An overview of Aspire is shown in Fig. 1. Aspire is built from three components. First, a closed-loop robot execution engine replaces coarse rollout-level feedback with per-primitive execution traces. For each perception, planning, grasping, and control call, the execution engine records the observations, inputs, outputs, and visual evidence if possible. These rich multimodal traces allow the agent to selectively inspect salient primitive logs, progressively localize failures, and validate repairs through re-execution. Second, Aspire maintains a growing skill library that distills validated fixes into reusable, transferable robotic knowledge retrievable as in-context guidance for future tasks. Third, Aspire employs an evolutionary search procedure that generates diverse task sequences and control programs, exploring beyond single-trajectory self-improvement through iterative debugging and parallel refinement. Together, these components establish a self-improving robotic system whose performance scales with experience: the more tasks Aspire sees, the larger its skill library grows, and the more it transfers to novel tasks, longer-horizon behaviors, and real-world robotic settings where similar failure-recovery patterns emerge under different embodiments.

Aspire 的总览见 Fig.1，由三个组件构成。其一，闭环机器人执行引擎以"逐原语执行轨迹"取代粗糙的 rollout 级反馈：每次感知、规划、抓取与控制调用都会记录观测、输入、输出，并在可能时记录视觉证据；这些多模态轨迹使智能体能有针对性地查看关键原语日志、渐进定位故障，并通过重新执行验证修复。其二，Aspire 维护一个持续成长的技能库，将验证过的修复蒸馏为可复用、可迁移的知识，并作为未来任务的上下文提示供检索。其三，Aspire 采用进化式搜索，生成多样的任务序列与控制程序，通过迭代调试与并行精化超越单轨迹的自我改进。三者共同构成一个性能随经验扩展的自我改进系统：Aspire 见过的任务越多，技能库越大，就越能迁移到新任务、更长时序的行为，以及那些在不同本体下重现相似"失效—恢复"模式的真实场景。

2. Method（总览）

方法开篇先复述三组件及其与论证目标的对应关系，再交代 coordinator–actor 架构与"上下文卫生"这一工程性理由。

2.1Aspire consists of three components that together form an open-ended learning loop: (1) a robot execution engine (§2.1) that exposes per-primitive multimodal traces for failure attribution and executes agent-written repairs for closed-loop validation; (2) a skill library (§2.2) that accumulates validated repairs as reusable skills; and (3) an evolutionary search procedure (§2.3) that broadens exploration beyond single-trajectory repair. As Aspire encounters more tasks, its skill library grows, allowing future tasks to inherit accumulated repairs and reusable strategies.

Aspire 由三个组件构成，它们共同形成一个开放式学习循环：（1）机器人执行引擎（§2.1），暴露逐原语多模态轨迹以完成故障归因，并执行由智能体书写的修复以形成闭环验证；（2）技能库（§2.2），把经过验证的修复累积为可复用技能；（3）进化式搜索（§2.3），把探索范围拓展到单轨迹修复之外。随着 Aspire 遇到的任务增多，技能库随之增长，使后续任务得以继承已累积的修复与可复用策略。

2.1. Robot Execution Engine

对应引言缺口一。论证结构：既有反馈的两难（P1）→ 本文设计（P2）→ 具体案例（P3–P4），案例同时充当机制说明与有效性证据。

E1Embodied coding agents need execution evidence to debug robot programs. Prior methods expose this evidence through fixed, human-designed interfaces, typically as manually curated scene-level summaries or a set of pre-defined observations. This creates a trade-off: too little evidence can hide the failing primitive, while too much raw visual context can distract the agent from the causal chain that produced the failure.

具身编程智能体需要执行证据才能调试机器人程序。既有方法通过固定、人工设计的接口暴露这些证据，通常是手工整理的场景级摘要或一组预定义观测。这带来一个两难：证据太少会掩盖真正出错的原语，而原始视觉上下文太多又会分散智能体注意力，使其偏离导致失败的那条因果链。

E2Aspire turns this fixed feedback channel into an open-ended debugging environment. The robot execution engine records per-primitive multimodal traces for perception, planning, and control calls, exposes the trace to the coding agent, and executes agent-written repairs for closed-loop validation. For each primitive call, the trace stores the invoked API, inputs and outputs, return status, and relevant multimodal evidence such as RGB keyframes, overlays, grasp candidates, object poses, and motion-planning results. The agent does not receive full video frames; the engine keeps frames immediately before and after each primitive call together with the corresponding overlays and return values, so the agent can focus on evidence around calls implicated by the failure.

Aspire 把这条固定的反馈通道改造成一个开放式调试环境。执行引擎为感知、规划与控制调用记录逐原语的多模态轨迹，把轨迹暴露给编程智能体，并执行智能体写出的修复以实现闭环验证。对每次原语调用，轨迹记录被调用的 API、输入与输出、返回状态，以及相关多模态证据（RGB 关键帧、叠加图、抓取候选、物体位姿与运动规划结果）。智能体并不接收完整视频帧；引擎只保留每次原语调用前后紧邻的帧，连同对应的叠加图与返回值，从而让智能体聚焦于与失败相关的调用附近的证据。

2.2. Skill Library

对应引言缺口二。论证要点：技能从"验证过的修复"归纳而来，形态是紧凑的上下文提示，准入由协调者审计。

S1Program failures recur across tasks, but the reusable knowledge is rarely an entire task program. Aspire's skill library stores heterogeneous repair knowledge: localization heuristics, perception prompts, grasping constraints, navigation recovery strategies, motion primitives, scene-understanding routines, and debugging workflows. We do not prescribe this taxonomy in advance. Skills are induced from validated repairs: the coding agent diagnoses a failure from execution traces, patches the program, validates the fix on debugging configurations, and the coordinator admits only reusable patterns into the shared library.

程序故障在不同任务间反复出现，但可复用的知识很少是整段任务程序。Aspire 的技能库存储的是异构的修复知识：定位启发式、感知提示词、抓取约束、导航恢复策略、运动原语、场景理解流程与调试工作流。我们并不预先规定这一分类体系：技能是从经过验证的修复中归纳出来的——编程智能体依据执行轨迹诊断故障、给程序打补丁、在调试配置上验证修复，协调者则只把可复用的模式纳入共享库。

2.3. Evolutionary Search

第三组件的论证走"自我批评→补丁"路线：先承认前两组件会陷入局部修复，再引入群体搜索。这是全文最自觉的一处让步式推进。

V1Trace-guided debugging alone can collapse into local repair loops, where the agent repeatedly patches the same failed strategy instead of exploring fundamentally different ways to solve the task. Aspire uses evolutionary search to broaden exploration of executable robot programs, encouraging diverse repair hypotheses and task strategies.

仅靠轨迹引导的调试容易坍缩为局部修复循环：智能体反复在同一条失败策略上打补丁，而不去探索根本不同的解题方式。为此 Aspire 引入进化式搜索，拓宽对可执行机器人程序的探索，鼓励多样化的修复假设与任务策略。

论证的自我修补环节：把 §2.1 的局限说清，才使第三组件成为"必需"而非"锦上添花"，从而让三组件结构显得不可减省。

V2In each round, based on the skill library, the coding agent proposes a population of K candidate programs conditioned on the top-performing previous programs and failure traces from previous evaluations. Each candidate is executed in the robot execution engine, producing task outcomes together with new diagnostic traces. The next round is then conditioned on the best-performing programs together with their remaining failure modes, allowing the search to explore distinct strategies rather than repeatedly refining the same solution.

每一轮中，编程智能体基于技能库、以往表现最好的程序以及上一轮评估留下的失败轨迹，提出 K 个候选程序构成的种群。每个候选都在机器人执行引擎中运行，产出任务结果与新的诊断轨迹。下一轮则以表现最佳的程序及其残余失败模式为条件继续生成，从而让搜索探索彼此不同的策略，而不是反复打磨同一个解。

3. Experiments · 3.1 Setup / 3.2 Benchmarks & Baselines / 3.3 Protocol

实验开篇不谈结果，而是先立"公平比较"的制度：固定 agent/环境/API、明确基线类型、以及训练—评测种子不相交。这三段是为 §3.4–3.7 的证据做可信度担保。

3.1For all the simulation benchmarks, we use Claude Code with Claude Opus 4.6 and a 1M-token context window as the coding agent. The agent writes executable Python robot programs in CaP-X, an open-source code-as-policy framework built on MuJoCo Playground, with robot programming APIs for perception, geometry, and motion planning. The agent, environment, and API set are fixed across all experiments.

4. Related Work

相关工作不是罗列，而是两次"划界"：对 agentic robot control 划出"持久性"，对 skill library 工作划出"知识来源"。

W1Agentic robot control. Robot control has been studied through end-to-end vision-language-action policies and executable programs that compose perception, planning, and control APIs. Software-engineering agents provide a related write-execute-debug loop for code. Aspire builds on the executable-program paradigm, but focuses on persistent embodied improvement: the agent freely selects primitive-level multimodal traces, writes repairs, validates, and preserves successful experiences across tasks.

智能体化的机器人控制。机器人控制沿两条路线被研究：端到端的视觉—语言—动作（VLA）策略，以及把感知、规划与控制 API 组合起来的执行程序。软件工程智能体则提供了类似的"写—跑—调"循环。Aspire 建立在可执行程序范式之上，但关注"具身的持久改进"：智能体自由选取原语级多模态轨迹、写出修复、加以验证，并把成功经验跨任务保留下来。

① 段落功能
第一次划界
② 逻辑角色
差异词是 persistent（持久），与 §1.3 缺口二呼应，将本文定位为"生命周期"贡献而非"单次求解"贡献。

W2Self-improving agents and skill libraries. LLM agents have been improved through open-ended memory, skill libraries, and self-evolving skill repositories. Other systems use LLMs to generate rewards, curricula, environments, or search candidates. Unlike success-only memories, textual reflections, or reward functions for downstream policy training, Aspire stores validated repair knowledge extracted from attributed embodied failures. Its skills are open-ended in both content and admission: they emerge from the agent's own debugging experience, span heterogeneous categories (§2.2), and are reused as in-context guidance for future program repair. Evolutionary search (§2.3) further broadens the space of executable program repairs before reusable patterns are admitted to the library.

5. Limitations

五条局限实为五处预设反驳的主动承认。分析价值在于：其中至少两条直接触及本文核心主张的成立条件。

L1Aspire has several important limitations. First, while selected simulation-discovered skills support autonomous real-robot debugging on a different embodiment, our system is not yet a fully autonomous real-world lifelong learner. Unlike simulation, where success checking and scene resets are cheap and programmatic, real-world deployment still requires robust success detection, safe reset, safety monitoring, and calibration maintenance. Future work should close this evaluation-and-reset loop to scale sim-to-real skill transfer across broader real-world task suites.

Aspire 存在若干重要局限。其一：尽管部分由仿真发现的技能能够支撑在另一本体上的自主真机调试，本系统仍不是一个完全自主的真实世界终身学习器。与仿真中廉价且可编程的成功判定与场景复位不同，真实部署仍需要稳健的成功检测、安全复位、安全监控与标定维护。未来工作应闭合"评测—复位"这一环，以便在更广的真机任务集上扩展仿真到真实的技能迁移。

6. Conclusion

结论段以"复述主张 + 分级证据"收束，并再次为迁移结论加上限定词。

C1We present Aspire, a continual learning robotic system that autonomously writes and refines robot control programs while compounding experience into a reusable skill library. Aspire operates in an open-ended learning loop with three components: a closed-loop robot execution engine that exposes fine-grained multimodal traces, a continually expanding skill library that distills validated fixes into transferable knowledge, and an evolutionary search procedure that explores diverse task sequences and control programs. Across diverse benchmarks, Aspire substantially outperforms existing VLA and coding-agent baselines, demonstrates strong zero-shot transfer to unseen long-horizon tasks, and provides initial evidence that the skills discovered in sim can transfer across embodiment to significantly reduce real-robot programming token cost despite different robot embodiments and APIs.

我们提出 Aspire：一个持续学习的机器人系统，它在自主编写并精化机器人控制程序的同时，把经验复利式地沉淀进可复用的技能库。Aspire 运行于开放式学习循环，包含三个组件：暴露细粒度多模态轨迹的闭环机器人执行引擎、把已验证修复蒸馏为可迁移知识的持续扩张技能库，以及探索多样任务序列与控制程序的进化式搜索流程。在多种基准上，Aspire 显著超越现有的 VLA 与编程智能体基线，展现了向未见长时序任务的强零样本迁移，并提供了初步证据：在不同机器人与不同 API 的条件下，仿真中发现的技能仍可跨本体迁移，从而显著降低真机编程的 token 成本。

One-sentence central claim · 中心主张一句话版 只要给编程智能体提供逐原语的多模态执行轨迹，并把经过验证的修复沉淀为可检索的技能库、再用进化式搜索扩大假设空间，机器人程序就能被自主写出、跨任务复用、并在性能上随经验持续增长——"调试经验复利"而非"更强的单任务求解器"才是机器人编程规模化的关键。
Strongest point · 最强论证 主张与证据的对应关系严密，且评测口径主动收紧。引言的两个缺口逐字映射到两个组件与两组实验：缺口一（归因难）→ 执行引擎 → 消融 14%→62%；缺口二（经验不累积）→ 技能库 → 库规模 N∈{0,25,50,90} 的零样本扫描。更关键的是 §3.3 的协议设计：调试/评测种子严格不相交，且 Aspire 每个任务只生成一个程序、禁止测试时重试，而基线可按种子重试——在对手更宽松的条件下取胜，使 +77 与 31% vs 4% 的差距难以用"算力不公平"解释。Fig.2 的 radio 案例还把"归因"这一抽象能力做成可核验的一次推理（感知成功 / 规划 PLANNING_ERROR / 目标落入 20cm 碰撞缓冲），机制可信度因此不依赖黑箱。
Weakest point · 最弱论证 "Open-ended"（开放式）这一核心形容词与系统的实际构造相矛盾，且承重假设未经验证。其一，§1.5 与摘要把"不再依赖固定人工流水线"作为卖点，但 §5 第三条承认程序只能在预定义 API 内书写，"不预设 taxonomy"（§2.2）也并未取消"何时可入库"由人工提示词规定的结构——开放性只存在于组合层，不存在于原子能力层。其二，"Program failures recur across tasks"（§2.2 第一句）与"经验能压缩成文本规则"是两项承重假设，前者缺少跨任务故障共现率统计，后者在真机上由 n=20、单平台、且更换了基座模型（Opus→GPT-5.5）的三任务对照支撑，证据量与主张幅度不成比例。其三，最直接的内部矛盾：§3.5 称成功率"increases consistently"，§5 又称库增长会带来"non-monotonic trends"与误导条目；技能库自身从未被消融（§3.7 只消融引擎与搜索），使得标题级的贡献缺少与 §3.4 同级的因果证据。
